# 기존 25개 역할·그룹 정책 확장

> 이전 단계 기록입니다. 현재 화면과 기본 입력은 MOCK300_GUIDE.md의 300개 완성본을 사용합니다. 추가 전후 비교 메뉴는 제거했습니다.

## 추가한 입력

기존 DB의 25개 사용자, 클라우드 배정, 메타데이터, 행동 값을 유지했다. AWS 9개 중 아래 대상에 연결 정보를 추가했다. 추가 설정은 사용자 요청에 따라 이번 로컬 구현에서 설계했으며 논문에 있던 원본 설정이 아니다. 실제 AWS API 호출은 없다.

| 그룹 | 기존 소속 사용자 | 정책 |
|---|---|---|
| ProjectReaders | admin01, userD | 프로젝트 문서의 s3:GetObject |
| StorageOperators | userA, userG | 프로젝트 스토리지의 s3:* |
| AutomationOperators | devops01, userJ | application-* 역할의 iam:PassRole, 전달 서비스 lambda.amazonaws.com 조건 |

| 전환 사용자 | 역할 | 역할 정책 |
|---|---|---|
| admin01 | ReadOnlyRole | 제한된 s3:GetObject |
| userM | StorageMaintenanceRole | 프로젝트 스토리지의 s3:* |
| userD | DeploymentRole | 조건부 iam:PassRole |

사용자별 sts:AssumeRole 허용 정책과 해당 사용자를 신뢰하는 역할 신뢰 정책을 함께 기록했다. 역할 정책을 사용자 권한으로 단순 합산하지 않는다. 그룹에는 새 사용자를 만드는 대신 기존 사용자를 소속시켰다. 역할은 사용자 25개와 구분되는 정책 분석 대상 3개다.

## 실제 분석 연결

- AWS 어댑터가 사용자 직접 정책, 그룹을 통해 받은 정책, 역할 정책을 출처 경로와 함께 추출한다.
- 사용자 직접·그룹 정책은 사용자당 하나의 정책 문서로 합쳐 기존 25개 전체 분석에 입력한다. 기존 조치 엔진이 첫 번째 정책만 읽고 나머지를 누락하는 상황을 피한다.
- 원래 정책 출처는 `aws_snapshot`에 별도로 보존하고 와일드카드·PassRole 검사와 화면에서 사용한다.
- 새 역할 3개에는 기존 행동 로그가 없으므로 AI 로그를 지어내지 않는다. 별도 정책 후보 검사를 수행한다.
- AI 입력과 보안 메타데이터는 동일하다. Azure/GCP의 입력과 점수도 동일하게 유지한다.
- 기존 `새 분석 실행·저장`은 확장 입력을 분석한다. DB 저장 시 그룹·역할 원본과 연결 정보도 함께 보존한다. 과거 DB 결과를 덮어쓰지 않는다.

## 확인된 결과

| 판정 | 추가 전 | 추가 후 |
|---|---:|---:|
| BLOCK | 1 | 1 |
| ALERT | 4 | 8 |
| ALLOW | 20 | 16 |

userA: 0.010→0.444, userG: 0.041→0.474, devops01: 0.039→0.172, userJ: 0.046→0.179가 ALLOW→ALERT로 바뀌었다. 그래프 단독 승격 기준도 있어 종합 점수 0.5 미만에서 ALERT가 될 수 있다.

admin01/userD/userM은 sts:AssumeRole이 기존 정규화 대응표에 없어 UNKNOWN으로 집계되며 점수가 각각 약 0.066 상승했지만 ALLOW를 유지했다. 이 변화는 현재 분석기의 동작을 보여 주며 실제 위험 확정 판정은 아니다.

역할 정책 포함 AWS 와일드카드 후보 4건, PassRole 후보 4건이다. 경로별 레코드 수이며 고유 취약점 수가 아니다. 역할별로 ReadOnlyRole은 두 후보 0건, StorageMaintenanceRole은 와일드카드 1건, DeploymentRole은 PassRole 1건이다.

## 화면과 파일

- `정책 사례 검증`: 기존 25개의 추가 전후 전체 분석, 사용자별 정책 출처, 역할 검사 결과, JSON/CSV 다운로드.
- `AWS 정책 분석`: 확장한 25개 중 AWS 원본을 기본 입력으로 사용. 이전 실제 AWS 수집 파일도 선택 가능.
- 별도 역할·그룹 예제 및 합성 30개 선택 메뉴는 화면에서 제거했다. 개발용 회귀 검사 파일은 보존했다.
- `data/mock25_extended.json`: 기존 25개를 확장한 통합 입력.
- 확장 파일의 `baseline_input`에는 추가 전 25개 원본도 보존한다. 비교 실행은 다른 환경의 DB ID에 의존하지 않는다.
- `data/mock25_extended_aws.json`: 사용자·역할·그룹 원본 구조.
- `validation/reports/extended25-analysis-report.json`: 전체 추가 전후 분석·출처·입력.
- `validation/reports/extended25-comparison.csv`: 25개 대상별 비교.

## 범위

역할 전환의 전체 유효 권한, SCP·권한 경계·세션 정책 및 다단계 권한 상승은 계산하지 않는다. 조건부 PassRole은 검토 후보이며 악용 가능성 확정이 아니다.

조치 후 결과는 사용자에게 전달된 정책 묶음의 시뮬레이션이다. 공유 그룹·역할 원본을 수정하고 다른 소속 사용자에게 변경을 전파하는 시뮬레이션은 아니다. 원래 대시보드와 실제 AWS 권한은 변경하지 않았다.
