## 기본 화면: 기존 DB 25개 전체 분석·검증

기본 입력을 DB에 저장된 기존 25개 데이터로 변경했다. 새로운 예제 입력을 생성하지 않고, 데이터셋과 연결된 이전 분석 결과를 읽어서 전체 파이프라인을 다시 실행한다. 입력과 과거 결과는 덮어쓰지 않는다.

- 정규화 → 규칙 → Isolation Forest → 권한 그래프 → 통합 판정 → 조치 시뮬레이션 → 재분석.
- 대상별 조치 전·후 통합 결과, 조치 계획, 조치 효과의 모든 저장 열을 이전 결과와 비교한다. 수치 허용 오차는 1e-9다.
- 최신 제공 논문 `한이음 논문 수정본_김태건,멘토보완 3p.hwp` 4.1~4.4의 인원·정규화 수·판정 건수·주요 5개 위험도와 판정·조치 대상 평균을 별도로 비교한다.
- 논문 이름 serviceAccount01/dataAnalyst01과 DB 이름 serviceaccount01/dataanalyst01의 표기 차이는 불일치로 보존하고, 점수 비교에 사용한 명시적 대응 관계를 화면에 설명한다. 계정 이름을 일반적으로 대소문자 무시하여 합치지는 않는다.
- 기존 DB 25개 역시 논문용 Mock다. 이전 결과 일치는 재현성 검사이며 독립적인 보안 정확도 평가가 아니다. 검증을 위해 새로 만든 프로그램과 화면은 이번 로컬 개발에서 추가한 것이다.
- AWS 9개에는 기존 Action 와일드카드·PassRole 후보 검사도 실행한다. 그룹·역할 연결 원본은 이 입력에 없으므로 그 경로는 검증 불가다. Azure/GCP에 AWS 전용 검사를 적용하지 않는다.
- JSON 전체 보고서와 25개 대상별 CSV를 다운로드할 수 있다. 내보낸 보고서: `validation/reports/saved25-validation-report.json`, `.csv`.

아래 별도 합성 정책 30개는 `검증에 사용할 데이터`에서 선택하는 보조 검사로 유지한다.

README 4번에 따라 합성 정책 30개를 실제 AWS 정책 검사기에 넣고, 명시적으로 작성한 기대값과 실제 결과를 비교한다.
이는 와일드카드·PassRole 후보 검사의 기능 검증이며 전체 보안 안전성이나 AI 탐지 정확도 평가가 아니다.

|---|---:|---|

| 미지원·오류 E01~E08 | 8 | NotAction/NotResource, 필수값 누락, 잘못된 Effect, 없는 그룹/정책 본문 거부 |

## 화면 사용

1. 왼쪽 `정책 사례 검증` 선택 후 `검증 실행` 클릭.
2. 분류·결과 필터로 사례 목록 확인.
3. `사례 상세`에서 목적, 기대값, 실제값, 세부 비교 항목과 후보 출처 확인.
4. `검증 입력과 정책 JSON`에서 원본 합성 입력 확인.
5. 전체 결과를 JSON 또는 CSV로 다운로드.

재실행 시 진행 표시와 완료 안내를 표시한다. 완료 안내에서 이번 접속의 실행 횟수와 마지막 실행 시각(한국 시간)을 확인할 수 있다. 같은 입력·코드로 재검증하면 결과 숫자는 동일할 수 있다.

통과는 기대 동작과 실제 동작이 같다는 뜻이다. 미지원·잘못된 입력을 올바른 사유로 거부한 경우도 통과이며, 해당 구문을 지원한다는 뜻은 아니다.
후보 없음은 현재 두 검사 항목이 없다는 뜻이며 최소 권한이나 전체 보안 안전성을 증명하지 않는다.
Allow와 Deny가 함께 있어도 Allow 구문의 후보를 보존한다. Deny·SCP·권한 경계 등을 결합한 최종 유효 권한 판정은 하지 않는다.
Describe*는 Action 패턴 후보이며 위험 확정 판정이 아니다. 동일 정책을 여러 경로로 받은 후보 수는 경로별 건수이며 고유한 취약점 개수가 아니다.

화면 검증은 메모리에서 실행하며 AWS 호출·권한 변경·원래 DB 수정은 없다.
검사 코드나 사례가 바뀌면 재실행 안내를 표시한다.

## 파일과 재실행

- `data/policy_validation_cases.json`: 사례별 입력·설명·기대 결과.
- `checks/create_policy_validation_catalog.py`: 사례 목록 생성 템플릿. 기대값은 검사 결과에서 자동 산출하지 않는다.
- `validation/policy_cases.py`: 실제 검사와 기대값 비교.
- `validation/dashboard.py`: 검증 화면.
- `checks/check_policy_validation.py`: 30개 사례와 실행기 검사 3개.
- `validation/reports/policy-validation-report.json`, `.csv`: 생성된 보고서.

보고서 재생성: `python -m validation.policy_cases`

전체 관련 검사: `python -m unittest checks.check_aws_role_policies checks.check_aws_group_policies checks.check_policy_validation -v`

총 60개 검사: 역할 12 + 그룹 15 + 정책 사례 30 + 실행기 3.
보고서에 실행 시각·사례 버전·사례 파일 및 검사 코드 SHA-256을 기록한다.

## 보강한 입력 처리와 범위

AWS Resource가 누락되거나 올바르지 않으면 임의로 *로 보충하지 않고 거부한다.
Condition이 주어졌을 때 객체 형식인지도 검사한다. 정책 의미 전체 해석과는 별개다.
기존 25명 Mock와 Risk 산식은 변경하지 않았다. 30개는 별도의 정책 기능 검증 사례다.
실제 로그 기반 AI 평가와 Mock 인원 확대는 포함하지 않는다.
처음 첨부된 원본 임시 폴더가 현재 비어 있어 기존 결과표 4개는 보관된 역할 단계 ZIP의 DB와 비교했다.
